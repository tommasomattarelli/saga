# SAGA v0.2.1-alpha.1 — 2026-08-01

## Highlights

### Installer

- Provider keys go in `backend/.env`, not "the in-app settings" the installer docs pointed at — there is no key UI. Following the old instructions gave you a working install that could not call a model, with nothing on screen saying why. Both installer READMEs now name the file.

### Memory & AI

- A provider failure no longer destroys the turn with an opaque crash (#50). OpenRouter reports a failing upstream model as **200 with `{"error": {...}}` in the body**, so `choices` is `None` and `choices[0]` raised `TypeError`. Every OpenAI-compatible endpoint now checks the response before indexing it and raises the upstream message and code. The action endpoint answers `502` with that reason instead of a generic `500`; the turn is not persisted and no narration is invented for it.
- Fact extraction caps each turn at five facts, but applied the cap to the model's raw output — one malformed entry ate a slot and the fact behind it was lost. The cap now counts only storable facts.

### Docs

- README rewritten for a public alpha: screenshots of a turn, an alpha notice, install first (native installers ahead of Docker), and sections on how the engine works and where it is going. Three claims were removed because they were false — three campaign templates in a `templates/` directory that ADR 0008 replaced with `worlds/`, API keys settable "via the UI", and an automated playtest bot that is a stub. The clone URL was a `<org>` placeholder.
- `LICENSE` shipped only the 17-line "how to apply" notice, so the project claimed AGPL-3.0 without its terms and GitHub classified it as "Other". Replaced with the verbatim text. `CONTRIBUTING.md` and `SECURITY.md` added.


## Internal

- Dependabot version updates paused (`open-pull-requests-limit: 0`, interval monthly) and the 23 open PRs closed. They had grown past one-at-a-time triage; they come back as one dedicated dependency pass. Security updates are a separate channel and stay on.
- `release.sh` accepts `-alpha.N`. The tags said `beta` while the README said alpha, and beta means feature-complete — which this is not.
- Model defaults refreshed. All three DM tiers pointed at the same `gemini-2.5-pro` — three tiers, one model, no routing. Now `gemini-3.5-flash` on low/medium and background work, `gemini-3.1-pro` on high. `docs/CONFIG.md` realigned with the file it documents; `.env.example` presets updated and its pointer to the non-existent `backend/app/ai/model_config.yaml` fixed. `OPENROUTER_API_KEY` and `LOCAL_MODEL_URL` documented — both wired, neither listed.
- `docs/AGENTIC_ARCHITECTURE.md` re-grounded in the code. Its data flow described `template.yaml → seed_templates → templates table`, dropped in migration `004_world_model`; rewritten as world → `world_baseline` (frozen) + `world_state` (overlay) → context, with the real overlay shape. Also corrected: salient psychology axes instead of a ±100 disposition scale, the missing NPC lifecycle tools, and `<abilities>` marked as not rendering (it reads `char_data["str"]` while the frontend writes `strength` — 0010-F1). Two limitations written down where the mechanism is: importance scoring is English-keyword-only, so any other language always scores 5 and always routes medium, and its combat bump reads a key with no writer. The v1/v1.5/v2/v3 roadmap, which predated ADRs 0002-0017 and contradicted several, is replaced by a table of the ADRs that change the turn loop.
- `eval/derive.py` — fills a built scenario's `context.*` and `fact_corpus` by driving the **real** memory subsystems over the authored transcript: batch compressor, rolling global summary, fact extractor. Kept separate from `scenario_build.py`, whose design is to be quota-free. No `--model` flag: routing goes through the router as production does, so a fixture is never summarised by a better model than the game will use. `--dry-run` prints the resolved provider and the call budget; every call is checkpointed, so a daily cap hit halfway resumes instead of paying twice.
  - `summary_context` mirrors `context._load_batch_summaries` rather than joining every batch: the reader takes the last five turn rows below the active window and dedupes, so only the last couple of batch summaries reach the prompt. Joining all four would build a context production never builds.
  - **Recall is authored per probe, not searched.** Production picks the top three facts by pgvector similarity; the harness has no vector store and each probe submits a different action, so "top three" is undefined at build time. Each probe names its own recall tokens, resolved against the derived corpus and capped at three, failing loudly on a miss. Ranking the corpus lexically would fold retrieval quality into a number meant to measure only whether the DM *uses* what it is handed.
  - `app.config` resolves `.env` from the cwd, so eval scripts run from `backend/` silently fell back to the YAML defaults. `derive.py` loads the repo-root `.env` first; `eval/model_smoke.py` has the same gap and is untouched.
- `extract_and_store_facts` split into `extract_facts` (prompt → parsed facts) and the storing wrapper — the derive pass needs the real extractor without a database, and the two were welded together against standard 7. Behaviour preserved.
- Model evaluation harness in `backend/eval/` (renamed from `backend/scripts/`) — measures whether a candidate model honours the DM's tool obligations instead of picking one on reputation. Drives the production prompt and tool schemas through five probes from playtest failures: a present NPC must route through `invoke_npc` (#52), a follow-up must not restate the line (#53), acquiring an object must call `add_item`, a passive turn must advance the clock, and an indirect inventory change must not be narrated without a matching call. Compliance is stochastic, so each probe runs `--runs` times and reports a ratio; provider failures are recorded as results, which also exercises the #50 class.
  - **Probes are orthogonal to scenarios**: `eval/probes.py` owns the checks, a scenario supplies world, context and stimulus. The same probe runs against an empty and a saturated context and the report prints the **Δ** — the drop under load is the number prompt work has to improve.
  - **Scenarios are derived, never hand-written**: a 25-turn transcript replayed through the real `apply_typed_updates` handlers, so every fixture state is one the engine can produce. Turn length is calibrated against production (1375 characters/turn, measured from the dev database). Variants are overlays on a `gold` baseline: `bloat` and `contradiction`.
  - The grader is unit-tested — it decides which model gets picked, so it must not lie. Expected language comes from the scenario; `gold` is authored in English because the world content is English and a codeswitched baseline would confound the measurement.
- `TODO.md` pruned (170 → 118 lines) with an explicit rule at the top: unlike ADRs the backlog is not append-only, so anything recoverable from `CHANGELOG.md`, an ADR, the git log or an issue gets deleted. Known defects migrated to issues: embeddings hardcoded to OpenAI (#55), Gemini `thought_signature` dropped (#56), hardcoded Postgres port (#57), Fedora unsupported by the installer (#58).
- ADR 0017 (NPC dialogue turn architecture) — **WIP stub, nothing decided**. From the `v0.2.0-beta.1` playtest (#52, #53): the mid-turn `invoke_npc` tool serialises the DM and NPC models (~7 sequential round-trips for a three-beat scene). Records the parallel pre-pass alternative, the constraint that the NPC's decisions stay its own, and six open forks. Next step is an owner design interview.
- Issue conventions (CLAUDE.md): titles follow the commit grammar, labels split into `type:`/`prio:`/`area:`, with title, priority and area set at triage and never asked of the reporter. New YAML forms in `.github/ISSUE_TEMPLATE/`, deliberately loose — bug report 130 → 55 lines, feature request 63 → 40. Discussions enabled for reports that are not bugs. Also recorded: an issue is for a defect or a user-visible ask (design work stays in `TODO.md`), and a branch is one reviewable unit of work, not one issue.
