# Changelog

All notable changes to SAGA are documented here.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

This log is curated by hand — it is not a dump of `git log`. Add entries under
`[Unreleased]` as you work, split into `### Highlights` (user-facing) and
`### Internal`. On release the notes move to
`docs/changelog/CHANGELOG-vX.Y.Z.md` (and the GitHub Release) and
`[Unreleased]` is reset; this root file keeps only `[Unreleased]`.

## [Unreleased]

### Highlights
- [Installer] The installer docs pointed the wrong way on the one step every new player has to take. They said to add the AI provider key "from the in-app settings" — there are no in-app settings for it: the backend reads provider keys from the environment, and the frontend has no key UI at all (it never did; the claim predates the REST rewrite). Anyone following the installer therefore reached a working install that could not call a model, with nothing on screen explaining why. `install/README.md` now names the file for both platforms — `%LOCALAPPDATA%\SAGA\app\backend\.env` and `~/.local/share/saga/app/backend/.env`, created by the installer with the other secrets already generated — and says to restart afterwards.
- [Memory & AI] An upstream provider failure no longer destroys the turn with an opaque crash (#50). OpenRouter does not report a failing upstream model with an HTTP error status — it answers **200 with `{"error": {...}}` in the body**, which the SDK deserializes into a response whose `choices` is `None`, so indexing `choices[0]` raised `TypeError: 'NoneType' object is not subscriptable`. The turn was lost, the player got a 500, and the two background writers (fact extraction, global summary) logged a type error instead of the real reason. Every OpenAI-compatible endpoint (OpenRouter, OpenAI, local servers) now checks the response before indexing it and raises an error carrying the upstream message and code ("Rate limit exceeded: free-models-per-day (code 429)"). This mostly hits `:free` models, the ones that saturate most often — which is what most self-hosted users are running. The action endpoint now answers `502` with that reason instead of folding it into the generic `500 DM processing failed`, so a throttled turn reads as something to retry rather than as a broken game; the turn is still not persisted, and no narration is invented for it (a fabricated turn would leave the world state disagreeing with what the player read).

### Internal
- `SECURITY.md` added, now that the repository is public and anyone can look for holes in it. Beyond the reporting channel (private advisory, never a public issue) it writes down the **threat model**, which is the part that saves both sides time: SAGA is single-player and self-hosted, so the boundary is one person's machine and their own provider keys, and a report is useful when it crosses that boundary — cross-account access, key exposure, injection that escalates past narration into tool calls or the host, an escape from the world-YAML or campaign-import parsers, XSS in rendered world content. It also says plainly what is *not* a vulnerability, so nobody spends an evening writing up the model saying something off-tone, or a `change-me` secret they set themselves.
- `docs/AGENTIC_ARCHITECTURE.md` re-grounded in the code and refocused on the agentic flow. Its data-flow section still described `template.yaml → seed_templates → templates table`, a pipeline whose table was dropped in migration `004_world_model` and replaced by worlds in ADR 0008 — it documented a schema that has not existed for a release. Rewritten as **world → `world_baseline` (frozen) + `world_state` (overlay) → context**, with the real overlay shape: UUID-keyed NPC records carrying `psychology`/`traits`, `player_position`, `node_status`, `edge_overrides`, `consumed_encounters`, `schema_version`. Three further drifts corrected against the live prompt builder: the scene block no longer renders a ±100 `disposition` (it renders only *salient* world-defined axes as band labels, ADR 0005 A5), the tool tables were missing `update_npc` and the NPC lifecycle tools and still named `change_npc_disposition`, and the `<abilities>` block is now marked as not rendering in practice — it reads flat `char_data["str"|"dex"|…]` while the frontend writes the full names, the key-convention drift owed to 0010-F1.
  - Two honest limitations written down where the mechanism is described rather than left implied: importance scoring is English-keyword-only, so a campaign in any other language always scores 5 and always routes to the medium tier, and its combat bump reads a key with no writer — the routing machinery works, the signal into it does not (ADR 0016). The Semantic Resolver section lost its "what it could become in v1.5" table and says instead why it is off: its jobs now belong to 0016 and 0002.
  - The `Ideas & Future Directions` and `Roadmap` sections (a v1/v1.5/v2/v3 ladder predating ADRs 0002-0017 and contradicting several of them — "Companion System [Future]" against 0014, "World Sim Agent" against 0006) are replaced by one table of the ADRs that change the turn loop, each with what it changes *about this document*. Roadmaps in a document describing production architecture rot silently; ADRs are the place where a direction carries its rejected alternatives.
- Model names refreshed everywhere a user copies them, and `docs/CONFIG.md` re-aligned with the file it documents. The shipped `saga.config.yaml` still routed every DM tier to the same `gemini-2.5-pro` — three tiers pointing at one model is not routing — while the reference doc had drifted to a different provider's names entirely, so the doc described a configuration nobody was running. Defaults are now `gemini-3.5-flash` on low/medium and background work, `gemini-3.1-pro` on the high tier, which is the first time the config actually demonstrates the tiering it exists for. `.env.example` had presets built on `gpt-4o` and `gemini-2.0-flash` and pointed at `backend/app/ai/model_config.yaml`, a file that does not exist — both fixed. The `provider: anthropic` example in CONFIG.md is deliberately left on Claude: the point of that block is that a tier can cross providers.
- README gained **"What SAGA is"** and **"Where it's going"**, between install and first run. The old "what makes it different" was six feature bullets, which answers *what it has* and never *why it is built this way* — the question a reader who is evaluating the project actually has. The new section states the four load-bearing ideas (the DM as a tool-calling agent whose narration must agree with the state it wrote; the engine owning every number the model would otherwise be argued into choosing; the world as authored data that persists whether or not the player is present; memory as a pipeline rather than a context window) and the fifth that is method rather than architecture — models are picked on harness measurements under a saturated context, not on reputation. "Where it's going" summarises the directions decided across the ADRs — director layer, NPC identity/lifecycle/promotion, relationship graph, deterministic combat, character progression, active abilities, commerce, language-agnostic importance routing, deeper worlds — in prose, without ADR numbers or per-bullet links, closing with one pointer to `docs/adr/`. Numbering ADRs at a reader who has not opened one tells them nothing; the point is the direction, and the records are there for anyone who wants the rejected alternatives.
- The README licence section says what the AGPL actually does — self-host and fork freely, redistribute or run modified as a service and the source goes with it — instead of one sentence of licence name-dropping, plus a line separating the code licence from the project name and branding, which the licence does not cover.
- Install section restructured around a **route table** (who each route is for, what it needs) with the per-route steps as copyable blocks — including the file to edit and the one line to add to it. It was four prose paragraphs that a reader had to parse to find out which of them applied to them, and the provider-key step, the only manual step in the whole flow, was a clause in the middle of a sentence.
- README rewritten as the front door of a public alpha rather than a feature list. The structure now goes pitch → **alpha notice** → **install** → first run, because the two questions a visitor has are "what is this" and "how do I run it", and installation used to sit below seventeen undifferentiated feature bullets. The native installers — the path for anyone who does not want Docker — were not mentioned at all despite shipping with every release; they are now the first install route, Docker the third. Added CI/release/licence/runtime badges (the CI badge is pinned to `?event=pull_request`, since CI runs only on pull requests and an unfiltered badge would read "no status" forever). Three claims were removed because they are not true: the repository has no `templates/` directory and no three campaign templates (worlds replaced them in ADR 0008, and one world ships, `the-awakening`) with a dead link to `templates/schema.json` behind it; provider keys cannot be set "via the UI"; and `tests.playtest.bot` is an empty stub whose body is a `TODO`, not an automated playtest. The clone URL was a literal `<org>` placeholder, so the first command of the quick start could not work.
- `CONTRIBUTING.md` added — an outside contributor had nowhere to look. The conventions existed only in `CLAUDE.md`, which is an agent instruction file: a human arriving from a GitHub issue will not open it, and should not have to read the whole working agreement to submit a typo fix. The guide covers reporting (issue forms vs. Discussions vs. private vulnerability reporting), local setup, the check commands CI runs, and the commit/branch grammar, and defers to `CLAUDE.md` for the rest instead of duplicating it.
- `.env.example` documents `OPENROUTER_API_KEY` and `LOCAL_MODEL_URL`. Both providers are wired in `ai/providers/base.py` and both are what a self-hoster on a budget actually reaches for, but the only file anyone copies listed three keys and neither of these — so the supported path was invisible and looked unsupported.
- `LICENSE` held only the 17-line "how to apply" notice from the end of the AGPL, not the licence itself — so the repository claimed AGPL-3.0 without shipping the terms it claims, and GitHub classified it as "Other" rather than as a known licence. Replaced with the verbatim FSF text (661 lines, unmodified, which is the condition for it being detected at all); the project copyright line moved to the README, where a copyright notice belongs and where it does not corrupt the licence body.
- `TODO.md` pruned (170 → 118 lines, no completed entries left) and given an explicit pruning rule at the top: unlike ADRs the backlog is not append-only, so anything recoverable from `CHANGELOG.md`, an ADR, the git log or a GitHub issue gets deleted, and only what would otherwise be lost stays — open work, operational warnings, and decisions recorded nowhere else. Removed every `design pass → absorbed into ADR NNNN` echo (the ADR is the record) and the completed implementation entries. Two rescues: the ability-key mis-keying entry was marked done while normalisation is still owed to `0010-F1`, so it is now an open item naming the three divergent conventions; and the vulture threshold warning moved to a new "avvertimenti operativi" section rather than dying with its completed entry.
- Model evaluation harness in a new `backend/eval/` (renamed from `backend/scripts/`, which held nothing else) — measures whether a candidate model honours the DM's tool obligations, instead of picking one on reputation. It drives the **production** DM system prompt and tool schemas (the campaign is a stub carrying only the attributes the prompt builder reads, so no database and no drift from a hand-copied fixture) through five probes drawn from the playtest failures: a present NPC answering must route through `invoke_npc` (#52), a follow-up step after an NPC result must not restate the line (#53), acquiring an object must call `add_item`, a passive turn must still advance the clock, and an indirect inventory change must not be narrated without a matching call. That last one distinguishes two failures that wear the same missing tool call — declining the action is merely unhelpful, whereas narrating a full turn as though it happened and recording nothing leaves the world state disagreeing with what the player read, with nothing downstream able to see the disagreement (dm.yaml:37 BACKSTOP). Each run is scored for missing/forbidden tool calls, language drift (#51), markdown, and mechanics leaking into narration. Compliance is stochastic, so every probe runs `--runs` times and reports a ratio; provider failures are recorded as results rather than raised, which also exercises the #50 class — and did, reproducing it twice on its first live run.
  - **Probes are orthogonal to scenarios**: `eval/probes.py` owns the checks and never moves, while a scenario supplies the world, the context and the *stimulus* (you cannot ask a model to pick up a knife at a menhir in a scene without one). The same probe therefore runs against an empty and a saturated context, and the report prints the **Δ** between them — the drop under load is the number prompt work has to improve, not the absolute score. Failure reasons are attributed per scenario so saturation-only failure modes are visible.
  - **Scenarios are derived, never hand-written** (`eval/scenario_build.py`, `eval/scenarios/`): a 25-turn authored transcript is replayed through the real `apply_typed_updates` handlers, so every fixture state is one the engine can actually produce, and node ids are seeded for a stable diff. Turn length is calibrated against production (1375 characters/turn, measured from the dev database) because a thin transcript under-fills the active window and makes the fixture easier than the thing it stands in for. Variants are overlays on a `gold` baseline, one hypothesis each: `bloat` (context length, via build parameters so the events stay byte-identical) and `contradiction` (self-inconsistent context, written to the same length so the two remain distinguishable). Filling the summaries and recall needs a `--derive` pass against a live provider and is not built yet; scenarios are flagged `derived: false` and the harness warns. `--dry-run` assembles every prompt and reports its size without calling a provider.
  - The grader is covered by unit tests — it decides which model gets picked, so it must not lie. The expected language comes from the scenario rather than being hardcoded, since `gold` is authored in English on purpose (the world content is English; a codeswitched baseline would confound the measurement, and English measures the ceiling of obligation-following).
- Known defects migrated out of `TODO.md` into GitHub issues, so the backlog file holds only design work, refactors and directions: embeddings hardcoded to OpenAI regardless of the configured provider (#55), Gemini `thought_signature` dropped and breaking multi-turn tool calls (#56), hardcoded Postgres port with a silent bind failure on Windows (#57), Fedora/dnf unsupported by the native installer (#58). Two entries were retired instead of migrated: the `getTurns` empty-render bug is already fixed by ADR 0013 Sprint 1, and the "verify the frontend pushes are fail-silent" item no longer applies — the WebSocket game handler was replaced by the REST turn endpoint, so there are no pushes.
- ADR 0017 (NPC dialogue turn architecture) — **WIP stub, nothing decided**. Opened from the `v0.2.0-beta.1` playtest (#52, #53): the mid-turn `invoke_npc` tool serialises the DM and NPC models (a three-beat scene costs ~7 sequential round-trips), the DM skips it or paraphrases its result, and the tool boundary breaks the rhythm of a scene. Records the parallel pre-pass alternative (~2 round-trips, reusing the existing `invoke_npcs_parallel`), the constraint that must survive any option (the NPC's *decisions* stay its own — the intent-only variant is disqualified), and six open forks including how it relates to ADR 0014's per-turn acting call. Next step is an owner design interview.
- Issue tracking conventions (CLAUDE.md "Issue Convention"): issue titles follow the commit grammar `type(scope): subject`, and labels split into three orthogonal axes — `type:`, `prio:` (set at triage, never by the reporter), `area:` (mirrors the commit scopes) — plus additive status labels. The GitHub default labels that mixed those axes were removed. New YAML issue forms in `.github/ISSUE_TEMPLATE/` (blank issues disabled); the feature form points at `TODO.md` and the ADRs first.
  - The forms were then **cut back to prose** before anyone had to use them. They had asked the reporter to write a Conventional Commit title and to pick an area from a dropdown labelled in the codebase's own vocabulary ("dm (DM loop, prompts, tools, NPC director)") — the two most expensive things to ask of a player and the two cheapest to fix at triage, so the title, `prio:` and `area:` are all triage outputs now and the forms ask for none of them. What stays required is only what decides whether a report is actionable at all: version, install + provider (one free-text line, not two dropdowns), what happened, how to reproduce. Bug report went 130 → 55 lines, feature request 63 → 40. GitHub Discussions were enabled to give the reports that are *not* bugs somewhere to land, and both forms point there.
  - CLAUDE.md gained the rules that were being applied without being written: an issue is for a defect someone can hit or a user-visible ask (design directions and refactors stay in `TODO.md`), and **a branch is one reviewable unit of work, not one issue** — related issues share a branch and close together via one `Closes #NN` each. The branching line was also corrected from `squash-merge` to **merge commit**, which is what the history has always done (`Merge pull request #NN`) and the only strategy under which the "series of small commits" rule buys anything.
