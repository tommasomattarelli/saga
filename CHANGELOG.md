# Changelog

All notable changes to SAGA are documented here.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Highlights
- [World & DM] NPCs now have a real psychology (ADR 0005): instead of a single friendliness score, every NPC tracks independent feelings toward you — trust, respect, affection and fear by default, and each world can define its own axes (honor, faith, …) with named intensity bands ("suspicious", "terrified") in the world editor. First meetings weigh ×3, reactions shift axis by axis from your actions and dialogue, and the DM sees only what stands out about each person present. World authors can seed starting feelings per NPC.
- [World & DM] Worlds replace templates (ADR 0008): campaigns are now created from a **world library** (`~/.saga/worlds`) holding reusable, file-authored worlds — hierarchical places (regions, sites, buildings, rooms) with real coordinates, travel routes with time cost (moving always costs game time, computed from distance, terrain and travel mode), travel encounters rolled on authored tables, and per-place status the story can change (a burning village stays burning). Each campaign plays on its own frozen copy — editing a world never touches existing saves.
- [World & DM] New **world editor**: create your own world from the "Worlds" page — define your own place types, terrains and travel modes (nothing is hardcoded), edit places/routes/factions/people/encounters in structured forms with picked references (no broken links possible), and share worlds as zip files (export/import). Every save is validated and versioned in a local git history.
- [UI] New in-game world map (read-only): a parchment-and-pins map of the campaign world, opened from a "Map" pill on the play screen — pan/zoom, breadcrumb between map levels, drill-down into places that carry a more detailed map, dashed travel routes between connected places, and a marker on the player's current position.
- [UI] Play screen redesigned to the new clean dark identity (ADR 0013, Sprint 1): self-hosted Newsreader/Instrument Sans type, verdigris accent, hero badge with level/HP, labeled panel pills, serif narration at reading measure with color-coded speakers, rounded action input in plain English, and a new tier-arc dice reveal showing all six outcome tiers. Also fixes: the orphan red companion bar, typed actions lost on a failed submit, history-load failures shown as a false "not started yet" empty state, and a CSS `@import` ordering bug that silently dropped every design token in dev.
- [UI] Redesign propagated to every remaining screen (ADR 0013, Sprint 2): auth is now a single centered card with visible boxed inputs (fixes invisible-input contrast bug); campaign list is a card grid replacing the book-spine shelf; new-campaign wizard flattened (no more 3D page-flip); character sheet is a tabbed rail modal on an opaque panel (fixes gameplay bleeding through); journal, settings, and combat tracker re-skinned to the same tokens. Plain English copy throughout, routed via i18n. Dead ornament assets (map, seal, book-spine, candles, flourishes) removed.
- [Installer] The native Linux installer now works on Debian and every Ubuntu release, not just Ubuntu 24.04: it adds the PostgreSQL PGDG apt repository so Postgres 16 + pgvector install uniformly regardless of the distro's default Postgres major (bookworm ships 15, trixie ships 17).
- [Installer] macOS: pgvector is now built from source against `postgresql@16` (Homebrew's pgvector bottle targets a different Postgres major, so `CREATE EXTENSION vector` previously failed).
- [Installer] The native Linux/macOS installer now fails fast with a clear message when run as root, instead of installing Postgres and then dying mid-way on `initdb` (which refuses to run as root).

### Internal
- ADR 0010 (player-character customization) design pass 2 — every remaining fork closed by owner interview, scope grown to **items**: new Item rulebook kind ("mega-class" à la 0009: authored definitions + typed runtime records, every inventory entry a record incl. flavor-only ad-hoc ones with bounded classes at creation), item **placements** on world nodes (overlay state machine placed→taken→dropped, authored items conserved, ad-hoc drops narrative-only), equip as UI rail action (first 0012-rail slice, applies C-layers + armor DR), **NPC inventories from `npc_classes` item pools** (uniform NPC schema as the companion-recruitability prerequisite), currency-as-item (commerce → future ADR). Progression numbers fixed: tier→XP grants incl. learn-from-failure, exponential ×1.6 curve, stepped skill-bonus table (+6 cap), XP-decay anti-farm on consecutive uses (roll never touched), skill level-ups feed char XP; char level = DM `grant_progress` magnitude tool + engine-drawn values, +1 ability point/level, +1 attribute point/5 levels. Resolution seam re-grounded on expanded 0003 (weights 1.0/1.0 in clamp [-5,+11], weapon items declare the skill that rolls and earns XP, DEX shifts player defense ±1 level at thresholds). Clean-restart assumption **revised to rung+seed** (typing rung on character_data, bundled default rulebook for pre-0010 worlds). Implementation plan fixed (S1 rulebook / S2 runtime / S3 progression / S4 items / S5 FE, ADR §7).
- ADR 0012 (active abilities) design pass — effect semantics settled by **dropping the numeric Power** for composition of the 0003 vocabulary (closed primitives: attack damage_class / heal heal_class / grants advantage; contested effects roll and can fail — worked anti-one-shot walkthrough; non-contested succeed with %-range magnitude); ability levels as authored per-level effect blocks bought with points (+1/char-level, unlock_cost + requires); **loadout cap** K active slots with swap-between-turns and a no-swap-while-on-cooldown rule; the **structured input rail** designed (single typed endpoint, engine gates, turn economy: ability use consumes the turn, item/swap/equip free but rate-limited; every rail action injects its fact into the DM context; backend authoritative), self-heals bound to it per 0003-B7b; targeting via F2 present-in-scene. Status/duration system stays the headline TODO. Implementation plan fixed (S1 core / S2 rail+FE / S3 economy, after 0010 S4).
- ADR 0003 (deterministic resolution) follow-up (same session): statblock gains **`npc_class`** anchored to world-taxonomy `npc_classes` templates (coarse archetypes with hp_class/defense/damage defaults; free `role` trait stays descriptive; derived threat display, authored numeric NPC level rejected), bounded creation classes for on-the-fly NPCs (`hp_class` weak→boss with config hp ranges), and the 0009 scaffold fix folded in (auto-created NPCs get `location = current node`); player defense DEX shift (±1 level, thresholds config) decided with 0010-E6.
- ADR 0003 (deterministic resolution) design pass — expanded in place from the combat-only 2026-06-09 draft to **one resolution system for every d20 check**; every fork closed by owner interview. Headline decisions: the LLM-set DC is removed everywhere — the LLM classifies difficulty into **6 literal levels** (`trivial`→`near_impossible`, anti-fluke by design) converted by the engine via **per-level RNG ranges** from config, against absolute outcome bands (5/10/15) with nat-only crits, advantage/disadvantage (binary + reason, replaces the ±N circumstance idea) and a character-modifier clamp `[-5,+11]` as the 0010 seam; **combat de-moded** — `start_combat`/`end_combat`/initiative/`combat_state` removed, one symmetric `attack(attacker, target)` for any pair (NPC-vs-NPC ready for companions), statblock on every 0009 record incl. the player (`hp`/`defense`-level/`attack_mod`/`damage_class`), mooks auto-created through the 0009 scaffold, Voyage-style always-on scene life bars; **server-side damage** — weapon classes × tier scale + attr mod, armor hook as %-reduction with total cap (values → 0010), hazards/heals as %-of-max-HP classes (anti-obsolescence), DM-initiated heals bounded by a scene-presence guard + config cap while the self-heal path (UI-selected potions/spells resolved engine-only in a turn pre-hook, no LLM in the loop) is fixed as a binding direction on 0012's structured input rail with 0010 item semantics; `apply_damage`/`update_hp` free-number tools removed; the three death modes fold into campaign difficulty (facile/medio/difficile), static death prompt block dropped; timed effects explicitly deferred to 0012. Implementation plan fixed (S1 resolver / S2 combat / S3 difficulty+death / S4 surfaces, ADR §7).
